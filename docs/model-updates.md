# Модели и долгосрочное сопровождение

## Что есть сейчас

Каталог `src/stem_local/models.py` содержит конкретные веса и конфигурации,
не названия «лучших моделей». Загрузка проверяет SHA-256, незавершённый файл
не становится готовой моделью. Перед инференсом проверка повторяется.
Исходные файлы приложения и старые результаты не удаляются при обновлении.

В GUI есть «Модели и обновления»: состояние кэша, источники, лицензии, SHA-256
и кнопка открытия актуального каталога MSST в браузере. Это **не автоматический
поиск**, не установщик произвольных checkpoint-файлов и не проверка наличия
новой версии приложения. Эти возможности пока не реализованы.

Никаких фоновых проверок обновлений или телеметрии в коде приложения нет.
Скачивание требует отдельного действия пользователя. Разделение не вызывает
онлайн-каталог `audio-separator`; сетевые операции Python блокируются audit hook,
FFmpeg допускает только протоколы `file,pipe`. Это не системная сетевая песочница.

Кнопка **«Проверить модели»** остаётся доступной, когда файлы уже скачаны.
После подтверждения отдельный worker проверяет SHA-256: исправные файлы не
скачиваются повторно, недостающие и повреждённые загружаются заново.
Повреждённый файл заменяется только после проверки новой копии; при ошибке или
отмене существующий файл остаётся на месте. Проверка не блокирует GUI.

## Как добавить проверенные веса

1. Найти первоисточник, условия использования **самих весов**, конфигурацию и
   поддерживаемую архитектуру. Наличие MIT у кода не лицензирует автоматически
   чужие веса. Для Kimberley MIT заявлена в карточке весов; для Demucs используется
   лицензия авторского репозитория с опубликованной там моделью. ViperX не очищен
   для распространения и требует отдельного согласия пользователя.
2. Зафиксировать revision/версию источника. Вычислить/сверить SHA-256 весов
   и точной конфигурации по доверенному источнику. Контрольная сумма не является
   доказательством лицензии и не делает неизвестный checkpoint безопасным.
3. Добавить отдельный `ModelSpec` с новым `id` в `models.py`, не изменяя старый.
   Для совместимого RoFormer используется роль `vocals`, архитектура `MDXC`.
   Вокальный адаптер сейчас рассчитан на stereo/44100/FP32, один целевой vocal stem
   и контекст 801 STFT-кадров; другие требования требуют правки адаптера.
4. Для новой архитектуры или другого семейства инструментальных моделей добавить
   соответствующий адаптер в `backends/`, подключить через `create_engine` в `engine.py`,
    а не добавлять условные ветки в GUI. Контракт — `separate(audio, *, progress=None) -> audio` и `audit()`;
   все правила формы, частоты, CPU, сети и нормализации описаны в `engine.py`.
5. Проверить загрузку, отсутствие сети и GPU, тишину, короткий файл, стыки фрагментов,
   полную песню, экспорт, отмену и ресурсы на **каждой реально поддерживаемой ОС**.
6. Сравнить качество на одном и том же фрагменте без автоматической подмены
   пользовательской модели «более новой». Новизна весов не гарантирует улучшение.

Checkpoint-файлы могут содержать сериализованный Python-код. Не добавляйте веса
из случайных источников. Приложение сознательно не предлагает «загрузить любой .ckpt».

## Сопровождение приложения

- GUI (`gui.py`) не импортирует PyTorch и не зависит от архитектуры модели.
- Worker (`worker.py`) владеет жизненным циклом задач, журналом и отчётом.
- `engine.py` определяет нейтральный контракт и лениво выбирает адаптер.
- `backends/audio_separator.py` изолирует PyTorch и конкретный `audio-separator`.
- `audio.py` отвечает за чтение, перекрытие окон и экспорт.
- `uv.lock` фиксирует дерево зависимостей; обновления делаются отдельным изменением
  с повторным прогоном тестов, а не `pip install -U` при старте программы.

Qt/PySide6 — зрелый выбор, но ни библиотека, ни приложение не имеют гарантии
неограниченной поддержки. Авторский репозиторий Demucs архивирован и не развивается
активно; здесь используется реализация из зафиксированной версии `audio-separator`.
Обновления Python, PyTorch, ОС и форматов моделей могут потребовать сопровождения.
Готовые бинарные сборки, подпись macOS/Windows и автоматическое обновление приложения
остаются отдельным этапом.
